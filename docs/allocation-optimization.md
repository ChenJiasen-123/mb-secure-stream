# Poly1305 分配优化记录

2026-10-12，MoonBit 0.10.15、Node 24.18.0、Windows。合成文件，默认 NODE_OPTIONS。

Inspector 以 32 KiB 间隔采样并包含已回收对象：4 MiB 输入、1 MiB 分块、加密一次。优化前主要采样热点是 Poly1305。采样总分配约 813.6 → 427.9 MiB；这是累计分配估计，不是准确分配总数、存活堆或 RSS。各仅一次采样，不是置信区间。

修改仅在 Poly1305 字节装载和临时缓冲：17 元素块数组在单次 MAC 内复用，部分块清理剩余字节；先在 UInt 中拼装、移位和掩码，再将五个 26 位 limb 转为 UInt64。乘法、累加、进位与模约减继续使用原 UInt64 计算，没有更换算法或放宽认证。

16 MiB 文件、1 MiB 分块，前后各三轮独立进程，均执行双向文件互通与八类异常验证：

| 操作 | 优化前耗时中位数（秒） | 优化后 | 前 RSS 中位数（MiB） | 后 RSS |
|---|---|---|---|---|
| 加密 | 2.831 | 2.081 | 366.1 | 382.3 |
| 解密 | 2.764 | 1.999 | 388.3 | 385.0 |

累计分配和耗时改善，RSS 未显著下降，加密峰值反而略增；不能声称解决了大块内存峰值问题。V8 GC/堆保留会影响 RSS，本次数据不能确定具体原因。保留 64 KiB 默认分块。当前比较只覆盖此平台、负载和参数，三轮顺序运行不能排除机器时变因素；不推导生产性能优势。

以下测试数量对应拆分前的历史提交，不代表当前精简主库。正确性：已有 RFC 向量、158 项全仓测试、8 项 secretstream JS 测试与 800 帧独立 libsodium 差分通过。另新增 86 个独立大整数 Poly1305 向量，覆盖 0—33 字节和跨多块的高字节输入，专门验证 UInt 拼装以及复用缓冲末尾残留；大整数 oracle 用 RFC 向量自检。加入后全仓测试数应为 159，最终以 CI 为准。

原始采样、三轮汇总及每轮数据均保存在 docs/measurements，汇总包含源码哈希与运行参数。复现工具为 tools/profile_secretstream_allocations.cjs 与 tools/measure_secretstream_repeated.py。Profiler 需要用户自行提供合成输入、演示密钥和不存在的输出路径；不打印密钥或明文。不要用敏感数据采样。

原始证据：[优化前分配采样](measurements/分配采样-优化前.json)、[优化后分配采样](measurements/分配采样-优化后.json)、[前三轮](measurements/分配优化前重复测量.json)、[后三轮](measurements/分配优化后重复测量.json)。各轮原始 JSON 与汇总位于同一目录。
